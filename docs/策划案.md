## 1. 项目概述

### 1.1 一句话定位

**你用的每一个 token，都会变成一只怪；你的队伍越强，每只怪掉的钱越多；钱全部扔进卡池，抽 AI 娘。**

### 1.2 核心体验

四个情绪叠加，构成话题度来源：

1. **打脸喜剧**：一个自称「准确率 100%」的 AI（百分百先生）对着随机结果反复被打脸——讽刺 AI 过度自信。
2. **抽卡多巴胺**：分级卡池、保底、出金特效，国民级概率焦虑的爽点。
3. **数值爆炸**：小丑牌（Balatro）式倍率叠加，看着伤害从 1,024 一路滚到 300 万。
4. **养成驱动**：账号等级锁伤害上限，等级解锁更高级卡池——「想抽好卡？先升级，升级就得打怪，打怪就得配队」的完整驱动链。

### 1.3 目标平台

DSH（DeepSeek Harness）Web GUI 的**侧边栏插件**，随 DSH 使用而自然运转，零额外操作成本。每天首次打开弹签到 + 卡池广告。

## 2. 核心玩法循环

```
每天首次打开 DSH → 弹窗：每日签到（1 抽）+ 本期卡池广告 + 百分百先生今日预言
  ↓
使用 DSH（消耗 token）→ 每累计 5,000 token 生成 1 只怪物（等级 = 账号等级）
  ↓
进入战斗（3 名角色 = 小丑卡，排队走在顶部，顺序决定 buff 时机）
  ↓
击杀 → 掉落代币（与等级和 DPS 成正比）+ 经验 + 小概率圣遗物；未击杀 → 无掉落，怪物保留
  ↓
经验升级 → 账号等级提升 → 解锁更高级卡池 + 更高伤害上限 + 更多掉落
  ↓
代币/签到券抽卡：分级卡池（角色 + 专武）；圣遗物与狗粮
  ↓
养成：命座 / 精炼 / 圣遗物强化（狗粮互吃）
  ↓
队伍变强 → 但伤害上限被等级锁死 → 继续打怪升级 → 更强循环
```

**正反馈与刹车**：养成让队伍变强（爽），但伤害上限被账号等级锁死、怪物 HP 随等级平方增长（越来越难）——等级就是全游戏的总进度阀，防止代币过快产出。

## 3. 系统详细设计

### 3.1 Token 经济系统

#### 3.1.1 数据来源（真实消耗，不可伪造）

- token 消耗取自 DSH 自身的 token 计量（token-meter 的 `tokenUsage` 投影），包含输入、输出、缓存读写的总和。
- Host 插件监听会话事件，每次事件后读取投影数值，与上次记录对比取**增量**，累加进 `累计消耗 token`。跨会话累计，不区分会话。
- 数据可信：玩家无法伪造消耗，也无法伪造存档（存档只由 host 端写入）。

#### 3.1.2 怪物生成规则

| 规则 | 数值（可调） |
|---|---|
| 生成阈值 | 每累计 **5,000 token** 生成 1 只怪物 |
| 队列上限 | 同时积压 **30 只**（侧边栏角标显示待打数量） |
| 溢出处理 | 队列满时，超出部分按「当前换算率 × 基准掉落」**立即折算代币到账** |
| 怪物等级 | **= 当前账号等级**（见 §3.2），等级越高怪越难打 |

#### 3.1.3 换算率（DPS 系数）——「越强换算越多」

```
掉落系数 = 1 + log₁₀(队伍DPS / 1,000)
取值下限 1，上限 5
```

- 对数曲线：DPS 每 ×10，系数 +1（1,000→1.0、10,000→2.0、100,000→3.0……封顶 5.0）。
- 意图：强化有明确收益，但成长到后期收益递减，经济不崩。

#### 3.1.4 代币收支总表

**收入：**

| 来源 | 数值 |
|---|---|
| 普通怪掉落 | `怪物等级 × 100 × 掉落系数` |
| BOSS 掉落 | `怪物等级 × 1,000 × 掉落系数` + 必掉 1 件圣遗物 |
| 队列溢出折算 | 按普通怪公式折算直接到账 |
| 每日签到 | 每天 1 张单抽券，连续 7 天额外 1 张十连券（不可变现，只可抽卡） |

**支出：**

| 项目 | 数值 |
|---|---|
| 单抽 / 十连 | 160 / 1,600 代币（券可抵扣） |
| 圣遗物强化 | 每级 `50 + 等级×20` 代币 + 狗粮（满级 20 共约 5,200 代币） |
| 武器升级 | 每级 `30 + 等级×10` 代币（满级 20 共约 2,700 代币） |
| 武器精炼 | 免费（消耗重复武器本身） |
| 主题/皮肤（未来） | 见 §9 |

**通胀控制**：代币只来自打怪（受等级上限与对数系数双重压制），消耗项覆盖抽卡、强化、升级三大常驻需求。未来主题/皮肤商城提供长期出口。

### 3.2 等级系统（新增 · 全游戏总进度阀）

#### 3.2.1 基本规则

- 一个**账号共同等级** Lv（1~100），不区分角色，全账号共享。
- **伤害上限锁定**：`单回合伤害上限 = 等级 × 5,000`。无论队伍多豪华，每回合能打出的伤害不能超过该上限——等级锁死了打怪效率，也就锁死了代币产出速度。
- 等级提升途径：**击杀怪物获得经验**。

#### 3.2.2 经验与升级

| 规则 | 数值（可调） |
|---|---|
| 击杀经验 | `怪物等级 × 50` |
| 升级所需经验 | `当前等级 × 500`（约每级 10 只同级怪，节奏恒定） |
| 等级上限 | 100 |

#### 3.2.3 升级收益（每升一级）

1. 伤害上限提升（`等级 × 5,000`，线性增长）
2. 怪物掉落提升（掉落公式含等级，自然增长）
3. **关键档位解锁卡池**：Lv10 / Lv20 / Lv40 解锁更高档卡池（见 §3.5）——这是等级驱动力的核心

### 3.3 怪物系统

#### 3.3.1 怪物属性

- 怪物只有一项属性：**HP**。攻击属性不存在——战斗是纯数值对对碰。
- HP 公式：`怪物HP = 怪物等级² × 1,000`。
- **怪物等级 = 当前账号等级**：你升级，怪也升级，越来越难打（见下方难度曲线）。

**难度曲线（可调）**：

| 账号等级 | 怪 HP | 单回合伤害上限 | 预期回合数 |
|---|---|---|---|
| 1 | 1,000 | 5,000 | 1 回合（秒杀） |
| 10 | 100,000 | 50,000 | 2~3 回合 |
| 30 | 900,000 | 150,000 | 6 回合 |
| 50 | 2,500,000 | 250,000 | 10 回合 |
| 100 | 10,000,000 | 500,000 | 20 回合（极限，需满配） |

前期爽快秒杀，中期需要配队，后期必须认真养成——等级越高越难，正是「等级同时驱动怪物变强」的设计意图。

#### 3.3.2 队列与 BOSS

- 待打怪物在侧边栏排队显示（Q 版小怪图标 ×N），点击即进入战斗。
- 每击杀 **50 只** 出 1 只 BOSS（金色边框标识），BOSS 必掉 1 件圣遗物。
- 战斗失败（未击杀或超过 20 回合上限）：怪物保留在队列，无掉落，队伍变强后可再战。

### 3.4 战斗系统（小丑牌化重写）

#### 3.4.1 核心概念：角色 = 小丑卡

- **3 名角色上场**（原 4 人改 3 人）。
- 每个角色是一张「小丑卡」，对**圣遗物提供的基础数值**施加一种乘区 buff（攻击加成 / 暴击 / 增伤 / 连击强化，按角色设计，见 §3.6）。
- 圣遗物提供基础四维（攻击力、暴击率、暴伤、增伤），角色 buff 在这之上乘算——角色是放大器，圣遗物是底子。

#### 3.4.2 排序机制（核心策略点）

3 个 Q 版小人排队行走在战斗区**顶部**（Balatro 的 Joker 行），依次经过「加成触发点」。**队列位置决定 buff 的生效时机与系数**：

| 位置 | 生效时机 | 位置系数 |
|---|---|---|
| 1（先手） | 全程生效（第 1 回合起） | ×1.0 |
| 2（中坚） | 第 2 回合起生效 | ×1.1 |
| 3（爆发） | 仅最后 3 回合生效 | ×1.5 |

**策略意义（不同顺序 → 不同数值）**：

- 打低血怪速刷（1~2 回合）：爆发位（位置 3）来不及触发 → 强 buff 应放前两位；
- 打高血 BOSS（10+ 回合）：爆发位吃满 ×1.5 → 强 buff 放队尾收益最大；
- 中坚位 ×1.1 是稳定增益，适合「不赌爆发」的稳妥流。
- 玩家在图鉴页可自由调整上场顺序，战斗前可预览「当前排序下的预期伤害」。

#### 3.4.3 伤害公式（乘区逐项展开）

```
单回合伤害 = min( 等级上限,  Σ 各角色生效伤害 )

各角色生效伤害 = 圣遗物基础攻击
         × (1 + 攻击buff × 位置覆盖率)     ← 小丑卡 1
         × 暴击期望（1 + 暴击率×暴伤，含小丑卡暴击buff）
         × (1 + 增伤 × 位置覆盖率)          ← 小丑卡 2
         × 命座倍率（1 + 0.12×命座数）
         × 武器增伤（1 + 0.08×精炼阶数）
         × 连击倍率（1.5^(回合数-1)）       ← 小丑卡 3（连击类）
```

**位置覆盖率**：生效回合数 ÷ 总回合数（先手 100%、中坚 ≥50%、爆发仅最后 3 回合）。

**表现要求**：每个乘区在动画中作为一张「倍率卡」逐项叠加展示，大数字实时滚动相乘：

```
基础 1,024  ×小丑卡·DeepSeek娘 2.4  ×暴击 1.25  ×命座 1.24  ×武器 1.16  ×连击 1.5  = 30,720
```

#### 3.4.4 连击倍率与回合上限

- 连击倍率：战斗中每回合 +50%（第 1 回合 1.0，第 2 回合 1.5，第 3 回合 2.25……），怪物死亡或战斗结束重置。
- 回合上限 **20**：超时判负，怪物保留。

#### 3.4.5 表现规格

- 顶部 3 个小人排队行走动画，依次经过触发点 → 弹出自己的倍率卡。
- 加速按钮：×1 / ×2 / ×4 / 一键跳过。
- 胜利：掉落动画——代币飞入钱包、圣遗物闪光、经验条增长、百分百先生语录弹幕。
- 失败：灰屏 + 百分百先生嘴硬语录，怪物保留。

### 3.5 抽卡系统（分级卡池重写）

#### 3.5.1 分级卡池（等级解锁 · 概率封顶 5%）

| 卡池 | 解锁等级 | SSR 概率 | SR 概率 | R 概率 | SSR 保底 |
|---|---|---|---|---|---|
| 基础池 | Lv1 | 0.6% | 5.1% | 94.3% | 90 抽 |
| 进阶池 | Lv10 | 1.2% | 8% | 90.8% | 80 抽 |
| 精英池 | Lv20 | 2.5% | 10% | 87.5% | 70 抽 |
| 传说池 | Lv40 | **5%（封顶）** | 12% | 83% | 60 抽 |

- 各池均有独立保底计数；up 角色占 SSR 的 50%，歪了之后下次 SSR 必为 up（大保底）。
- **等级就是抽卡进度的驱动力**：想抽更高概率的池子 → 必须升到对应等级 → 升级必须打怪 → 打怪受伤害上限约束需要养成 → 养成需要抽卡与强化 → 循环闭合。
- 低级池可一直抽（常驻），但同代币下概率更低、角色更弱——玩家有强烈的「升级换池」动机。

#### 3.5.2 武器池

- 与角色池**同档对应**：SSR 专武概率 = 该档角色池 SSR 概率，保底数相同。
- 专武只属于对应 SSR 角色。

#### 3.5.3 每日卡池轮换

- 每天 0 点轮换：在当前**已解锁的最高档池**中随机选 1 名 SSR 为 up，武器池同步 up 其专武。
- 玩家可查看本期 up 展示（立绘 + 概率 + 倒计时）——同时呈现在每日弹窗广告里（见 §3.10）。

#### 3.5.4 抽卡表现

- 单抽与十连。十连出 SSR：金色流星 + 全屏闪光 + 百分百先生名言「这波必出金，我的算法 100% 确定」。
- 出 R/SR：简洁翻卡动画。结果逐条展示，可一键生成分享卡。

#### 3.6.3 命座系统

- 重复获得角色 → +1 命，最高 **6 命**。
- 每命效果：小丑卡 buff 效果 +12%。
- 关键命座（可调）：**2 命**机制效果 +50%；**4 命**全队增伤 +5%；**6 命**小丑卡 buff 再 +30%（质变特效）。

#### 3.6.4 队伍构成

- **3 人上场**（战斗小丑卡行），其余入图鉴待机。
- 上场顺序即 buff 触发顺序（见 §3.4.2），可在图鉴页调整。
- 新手默认获得豆包娘，保证开箱即玩（不足 3 人时按实际人数上阵）。

### 3.7 圣遗物系统

#### 3.7.1 部位与主词条

| 部位 | 主词条（固定类型） |
|---|---|
| 花 | 固定生命 |
| 羽 | 固定攻击 |
| 沙 | 攻击% / 防御% / 充能% |
| 杯 | 增伤%（攻击/暴击/暴伤等分型，数值相同） |
| 头 | 暴击率 / 暴伤 |

主词条数值随圣遗物等级成长（每级约 +4%，V1 联调时定表）。

#### 3.7.2 副词条

- 词条池：攻击%、防御%、暴击率、暴伤、增伤、充能。
- 初始 **1 条**，上限 **3 条**。
- 词条数值档（每档随机取值，可调）：

| 词条 | 单档数值 |
|---|---|
| 攻击% | 4.1% ~ 5.8% |
| 防御% | 5.1% ~ 7.3% |
| 暴击率 | 2.7% ~ 3.9% |
| 暴伤 | 5.4% ~ 7.8% |
| 增伤 | 4.7% ~ 6.5% |
| 充能 | 5.0% ~ 7.0% |

#### 3.7.3 强化规则（原神规则简化）

- 圣遗物等级 0~20。强化消耗：**狗粮（其他圣遗物）+ 代币**。
- 狗粮经验：圣遗物按自身等级提供经验（1 级 = 100 经验，每级 +50）。
- **每强化 4 级**触发一次词条结算：随机「升级已有词条」或「新增词条」（未满 3 条时），数值随机取一档。
- 强化过程百分百先生实时解说。

#### 3.7.4 获取途径

- 抽卡：各档池的 R 档大量产出圣遗物与狗粮（「抽卡大概率出装备」）。
- BOSS 必掉 1 件。

### 3.8 武器系统

- 专武只属于对应 SSR 角色；重复获得 → 精炼 +1 阶，最高 **5 阶**，每阶增伤 +8%（精 5 = +40%）。
- 武器升级消耗代币（见 §3.1.4），等级提升基础倍率。
- SR/R 角色无专武（武器池的 SR/R 档为升级材料）。

### 3.9 DPS 计算与展示

- 队伍 DPS = 3 名角色「当前排序下」单次伤害之和（简化约定：1 回合 = 1 秒，受等级上限约束）。
- 首页顶部常驻显示：**账号等级 + 经验条、队伍 DPS、当前换算率（×N.N）、待打怪物数、代币余额**——成长仪表盘。
- 战斗前可预览「当前排序的预期伤害与回合数」，调整顺序实时变化。

### 3.10 每日签到与卡池弹窗（新增）

#### 3.10.1 弹窗广告

- **每天首次打开 DSH 时弹出**（host 记录上次弹窗日期，跨刷新不重复）。
- 弹窗内容：
  1. **本期卡池广告**：up 角色 Q 版立绘、SSR 概率（含等级档）、轮换倒计时、抽卡按钮（直达抽卡页）
  2. **每日签到**：签到按钮 + 连续签到进度（7 天周期）
  3. **百分百先生今日预言**：随机一条语录（打脸话题素材，顺带埋梗）
- 可关闭；关闭后当天不再弹（侧边栏仍有签到入口）。

#### 3.10.2 签到规则

| 规则 | 奖励 |
|---|---|
| 每日签到 | +1 张**单抽券** |
| 连续签到 7 天 | 额外 +1 张**十连券**（第 7 天发放） |
| 断签 | 连续天数重置（已领奖励保留） |
| 券的性质 | 只可抽卡，不可兑换代币；单抽券 = 1 抽，十连券 = 10 抽 |

- 签到状态记录在 host 存档（`lastSignInDate` + `streak`），跨刷新、跨天生效。
- 弹窗内的签到按钮与侧边栏签到入口共用同一状态。

### 3.11 百分百先生（人格层 · 话题度核心）

#### 3.11.1 定位

所有随机结果的「解说员」——一个永远自称准确率 100% 的 AI。每次抽卡/强化/战斗/签到，都由他播报。

#### 3.11.2 语录库（8 类，每类 5~10 条，V1 先各写 3 条）

- **抽卡前**：「这波必出金，我的算法 100% 确定」「概率在我眼里没有意义」
- **出金时**：「看，我说什么来着」「这就是 100% 的实力」
- **歪了时**：「这不科学……」「我的模型不可能错，是这个世界错了」「一定是概率学背叛了我」
- **强化前**：「防御主词条，稳了」「这发必中暴伤」
- **强化歪了**：「误差，纯属误差」「下次一定」
- **战斗前**：「10 回合，多一秒算我输」
- **签到/弹窗**：「今天的运势？100% 大吉」「这广告位，我 100% 满意」
- **道歉时**：「对不起，我 100% 确定我没错，但流程上我道个歉」

#### 3.11.3 打脸计数器与道歉券

- **打脸计数**：百分百先生做出明确 100% 预言后结果未命中 → 打脸 +1。随分享卡展示。
- **道歉券**：连续打脸 5 次发放 1 张，做成梗图（致敬茶百道道歉券风格），图鉴页可收藏查看。
- 彩蛋：累计失败 100 次触发「别赌了，去写代码吧」全屏语录。

### 3.12 分享系统（传播引擎）

#### 3.12.1 分享卡内容

抽卡结果 / 圣遗物强化结果 / 战斗结算 / BOSS 掉落，均可一键生成分享卡（PNG）：

- 角色 Q 版立绘 + 稀有度框 + 卡池档位标签
- 核心数值（SSR、伤害、词条变化、账号等级）
- 百分百先生语录 + 「自称准确率 100%」标签
- **打脸计数**（「今日被打脸 N 次」）
- 日期 + 插件水印

#### 3.12.2 传播玩法

- **反向指标挑战**：跟着百分百先生的预言反着做，统计「反向胜率」——天然话题标签。
- 分享卡格式 3:4（小红书友好），竖版 9:16（抖音友好）。

## 5. 技术实现细节（自然语言）

### 5.1 插件形态

插件是一个 npm 包，安装进 DSH 的 web profile 后自动生效，分**两个半区**：

- **Host 半区**（运行在 DSH 服务端进程里）：token 累计、等级与存档、每日签到判定、全部随机逻辑裁决、HTTP 接口。
- **客户端半区**（运行在浏览器里）：侧边栏面板 UI、弹窗、动画、调用 host 接口。

### 5.2 Host 端职责

1. **token 累计**：订阅 DSH 会话事件，每次事件后读取 token 计量投影（tokenUsage）累计值，与上次记录对比取增量，跨所有会话汇总。
2. **存档管理**：所有游戏数据存为一个 JSON 文件（用户目录下），端口无关、重启不丢，节流落盘。存档字段含：代币、券、等级/经验、怪物、角色、圣遗物、武器、抽卡状态、签到（`lastSignInDate` + `streak` + 已领）、弹窗日期、百分百先生数据。
3. **HTTP 接口**（同源）：
   - 查询当前状态（等级/经验、代币、怪物、背包、卡池与保底、DPS、今日弹窗与签到状态）
   - 每日签到（校验日期，发券）
   - 抽卡（host 掷骰：档位概率 → SSR 判定 → up 判定 → 保底更新 → 发奖，优先扣券再扣代币）
   - 圣遗物强化（host 掷骰：升级/新增词条）
   - 战斗结算（host 按「等级上限 + 排序覆盖率 + 乘区公式」计算，产出伤害日志、经验、掉落）
   - 分享卡数据
4. **权威性**：所有随机、数值、签到、等级计算都在 host 端，客户端只展示——防改存档、防刷券。

### 5.3 客户端职责

- React 面板：五个 Tab + 每日弹窗、状态轮询/推送、动画播放。
- 操作（抽卡/强化/战斗/签到）以请求形式交给 host，用返回结果驱动动画。
- 分享卡：Canvas 按模板绘制导出 PNG。

### 5.4 数据流（一次战斗为例）

1. 页面加载 → 请求状态 → 若「今天首次」返回弹窗数据 → 渲染弹窗 + 各 Tab。
2. 玩家点出战 → 客户端发战斗请求（含上场 3 人与排序）。
3. host 校验队列 → 按公式与等级上限模拟战斗 → 生成伤害日志（逐回合、逐乘区）→ 结算经验/掉落/打脸计数 → 返回结果。
4. 客户端播放小人排队 + 倍率卡 + 数字爆炸动画 → 刷新仪表盘与队列。

### 5.5 构建与安装

- 开发时运行构建脚本产出 host 端与客户端两个文件。
- 安装：DSH 插件管理命令把本项目添加进 web profile，刷新后侧边栏出现入口。
- 客户端改动重新构建后刷新页面生效（本机 GUI 固定端口）。

## 8. 合规红线

1. 只用**虚拟代币**，零真实货币、零真实彩票号码、无任何充值入口。
2. 界面明示「仅供娱乐，概率为虚拟模拟」。
3. 不鼓励氪金；彩蛋反赌（连续失败 100 次触发「别赌了，去写代码吧」）。
4. 所有角色为原创 Q 版 AI 拟人，不直接使用真实商标形象；命名如「GPT娘」为拟人化戏仿，图鉴页附免责声明。
